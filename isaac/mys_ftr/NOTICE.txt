MYS FT-R Isaac Sim deployment

This directory runs a user-provided, frozen Booster T1 foothold-tracking actor.
It is separate from the ADAPT G1 velocity-tracking policies.

The actor export, root-frame observation adapter, stance-based target generator,
and nominal robot model were derived from Mind Your Steps / LocoMuJoCo:
https://github.com/MontenegroAlessandro/loco-mujoco
Source checkout: 5d174e5f622851b0ba8222f19384a437f25913fb (with local training changes).
The included LICENSE.loco-mujoco preserves the source repository's MIT notice.
Booster T1 visual meshes are copied from that repository's booster_t1/assets.

actor.npz contains actor weights and frozen observation mean/variance only.
The original user-provided checkpoint SHA256 is recorded in export.json.
This is not an official MYS checkpoint release or an exact paper reproduction.
The bundled actor passes a 25 s forward and a 25 s stand/forward/turn/stop GT
rollout in Isaac Sim 5.1. No estimator, payload or training is enabled.
IMU / RTX radar recording is optional (--imu / --radar); policy input stays GT.
PhysX and MuJoCo contact/friction solvers are different; the port preserves
joint order, FK, masses, PD gains, action scaling and torque limits.

Runtime: existing Isaac Sim 5.1 Python environment (Python 3.11, NumPy, SciPy).
Do not install ADAPT's Python 3.10 environment into this separate environment.
view.sh uses the active python, or ISAAC_PYTHON if provided. USD is generated
on the first launch. Run artifacts are ignored under runs/ and usd/.

Re-export (optional; requires the source MYS environment):
python export_policy.py --checkpoint /path/policy.pkl --mys-repo /path/loco-mujoco

Red target: left foot. Blue target: right foot.
Default schedule: 0-2 s stand, 2-12 s forward (0.25 m foothold displacement),
12-16 s turn 10 degrees per step, 16-25 s stand. Gait frequency is 1 Hz.
These are foothold commands; no global waypoint or heading-hold controller.

Runtime timing: physics, GT state reads/logging and PD torque updates are 1 kHz
(1 ms). Policy inference, foothold phase updates and rendering remain 50 Hz
(20 ms, 20 physics steps per action). This is simulation time, not a wall-clock
real-time guarantee. Native IMU / radar streams require explicit sensor flags;
no state-estimator stream is generated.
export.json retains the source model's 5 ms / 4-step training metadata;
setup.json records the deployed 1 ms / 20-step timing.
trace.npz samples the state before each physics step. root_lin_vel (m/s) and
omega_world (rad/s) are world-frame GT velocities. torque (Nm) is the clipped
PD + damping + friction compensation torque actually applied on that step.
observation/action/targets/command/phase hold the latest 50 Hz policy values;
is_policy_step marks fresh actor calls and policy_index identifies each call.
Select trace['is_policy_step'] to recover the 50 Hz policy-time samples.

Optional sensors (GT policy feedback remains unchanged):
- --imu: torso-origin native IMUSensor at 1 kHz, identity mount, filters 1.
  imu.npz contains native timestamps, receipt_time, sensor-frame specific_force
  (+g at rest), angular_velocity and orientation_wxyz_gt for reference only.
  Initial reading times can precede delivery by one physics tick; no resampling.
  IMU noise/bias has not been calibrated to the user's hardware.
- Default --radar profile: ti_awr1843aop, Booster Trunk chest location
  [0.16,0,0.16] m with +Y pitch 20 deg (boresight points down), roll/yaw zero.
  This is the user-approved Booster mounting assumption, not K1 head CAD.
  No added pillars by default. --radar-reflectors adds the earlier diagnostic.
  Native WPM DMAT with Motion BVH / GMO rv_ms remains the base radar model.
- TI-inspired detector settings: range resolution 0.065 m, max range 5 m;
  velocity resolution 0.08 m/s, max unambiguous velocity 2.48 m/s and detection
  gate +/-2.49 m/s; azimuth/elevation resolution 30/38 deg; FOV +/-60/60 deg;
  CFAR range and velocity test/guard cells 8/4, binsFromSpec true.
  These are point-cloud/detection approximations, not a TI waveform/ADC emulator.
  source_cfg_sha256 in sensors.json identifies local 1843_Standard_Good.cfg.
  Its comments say 100 ms, but frameCfg is 66.6 ms. We explicitly override output
  to 10 Hz per user request; we do not claim literal replay of that cfg.
- Both native and synthetic points receive independent Gaussian perturbations:
  range 0.01 m, Doppler 0.015 m/s, azimuth 2 deg, elevation 3 deg; then range and
  Doppler are quantized to 0.0488 m / 0.0762 m/s. Extra native angular/range noise
  is disabled in this profile. --sensor-seed controls this independently of robot
  initial-state seed. Real-bag 35 distinct velocities / 24% zeros are descriptive
  statistics, not forced output targets: they depend on motion and scene.
  Physical range/FOV/velocity gates act before measurement noise; measured values
  may slightly exceed those boundaries after noise / rounding.
- Synthetic surfaces: local real_floor_model.npz (0916 run_02) provides empirical
  requested counts and direction/intensity samples. SHA256 is saved. The file is
  intentionally ignored by Git; see calibration/README.txt for setup.
  Sampled gravity-aligned directions are cast against current PhysX COLLISION
  geometry at the actual render/acquisition time and cached until matching native
  RTX delivery. Slopes/steps/pads follow the hit surface; points are not forced
  onto z=0. Robot and dynamic first hits reject rays, without seeing through them.
  Visual-only objects have no PhysX ray occlusion. Requested counts can decrease
  due to range/FOV/occlusion; no success counts are forced.
  Surface Doppler is a GT-driven static-scene forward model using the actual
  nominal sensor-pose change over the native render interval (rotation lever arm
  included). It is SYNTHETIC, not rv_ms from RTX, and is labelled per point.
  This point simulator is not independent evidence of real-estimator accuracy.
- Optional --radar-ray-origin-offset moves RTX rays along radar +X; native XYZ
  is shifted back to the nominal mount. Default is ZERO because no Booster CAD
  correction was supplied. Native Doppler is preserved at the ray origin; with
  a nonzero shift, its small rotation-dependent lever-arm difference is not
  corrected using GT. Both translations and the offset are recorded.
- --radar-profile generic uses the earlier native-only detector (no empirical
  model or added measurement noise). Use --radar-pitch-deg 0 --radar-reflectors
  to reproduce the earlier forward-looking pillar diagnostic. --no-synthetic-floor
  disables the surface sampler in the TI profile; native flat-floor frames may
  then be empty. Empty native frames are not filled invisibly.
- radar.npz uses offsets[N+1] into concatenated point arrays. is_synthetic is
  true for surface samples; xyz_before_measurement_model and
  velocity_before_measurement_model preserve input to the added noise model.
  native_count / floor_target_count / floor_visible_count are per-frame counts.
  Scalar meanings differ by source: native WPM uncalibrated scalar versus sampled
  real floor intensity. They are not asserted to be cross-calibrated CFAR SNR.
  Native header endpoint pose/quaternion fields ending in _gt are reference
  data only; do not feed them to the estimator.
- time is scan END in rollout simulation seconds; time_start preserves the start;
  receipt_time records delivery. timestamp_ns / frame_end_timestamp_ns preserve
  raw RTX clock values. Clock association matches native endpoint poses to render
  requests, fixes one offset, and validates both endpoints. Stale reset frames
  are rejected rather than retimed to improve task metrics.
- Rendering remains 50 Hz to keep latency low. Isaac 5.1 WPM tickRate does not
  reliably throttle native output; retain only scans ending on the 10 Hz grid.
  Actual scan integration windows are preserved. Physics, IMU, encoders and PD
  remain 1 kHz. This is simulation time, not a wall-clock realtime guarantee.
  Frozen actor / gait stay 50 Hz. No GaRLILEO feedback, ROS bridge or retraining.
- USD nonvisual steel materials use CSV-disabled mapping, with a nonempty legacy
  name map for Isaac 5.1 WPM compatibility; exact launch/settings are saved.
